Engine Lua globals

Applies to:
BGEE, BG2EE, IWDEE (patch 2.0 and later)

General Description
The user interface of the Enhanced Editions runs in one global Lua state that is shared by the MENU file, the game's own Lua files and the engine. This page lists the global variables and tables that the engine itself defines in that state, the structure of every table it fills, and the Lua functions it expects the game's Lua code to provide. The engine's Infinity_* C functions are not covered here; those that work on menus are described on the MENU Lua interface page.

The information comes from patches 2.6.6.0 and 2.7.3.0 of BGEE, BG2EE and IWDEE. All six builds define the same globals with the same structure; the only difference is listed under Version differences. Descriptions marked † are inferred from the names of the engine functions that write or read the value; the code that uses them was not traced in detail.

Start-up order.
  1. bootstrapLua creates the Lua state, opens the standard libraries _G, table, string, bit32, math and debug (but not io, os or package), replaces print, and runs the small Lua chunks that define options, SetPrivateProfileString, getOptionsSection, languages and setLanguageVisible.
  2. CLUAConsole::LuaInit registers the engine's C++ classes (tolua++ bindings), runs the binding's embedded Lua chunk that creates the engine objects, runs C = CLUAConsole:new() and then executes the file luaAuto.cfg.
  3. Later, during resource initialisation, dimmInit registers the Infinity_* functions, runs the Lua resource INCLUDES and loads UI.MENU.
  4. While the game runs, engine code sets single values with lua_setglobal, fills the data tables and calls the functions provided by the game's Lua.

Constants
These are all the constants the engine defines in Lua. The global ones are plain numbers registered by the bindings. The CTimerWorld ones are read-only static members of the class: they can be read through the class table (CTimerWorld.TIME_DAWN) or through the timer object (timer.TIME_DAWN), and they have no setter. Game time is counted in ticks: 15 ticks per second, 4500 per game hour and 108000 per day. timer:GetCurrentTime() returns the timer's tick counter, and timer:GetCurrentHour() returns (that counter modulo 108000) divided by 4500, i.e. the hour of the day (0–23).

Data tables
These tables are created or filled by engine code. Each structure lists the keys the engine writes and the Lua type it stores. [n] stands for a numeric index (lists start at 1), [string] for a key the engine builds at run time (for example an equipment slot name). A table written by “assigned by” functions is replaced as a whole; the others are created by the game's Lua and only filled by the engine. Fields called strRef, name, desc, description and helpStrRef that hold numbers are string references into dialog.tlk.

The bindings, the embedded chunk, the constants and their values, the globals set by the engine and the table structures are identical in all six examined builds. The only difference is the translation function the engine calls: t in 2.6.6.0 and getUiString in 2.7.3.0 (see also the MENU page).
