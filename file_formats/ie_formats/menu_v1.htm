--- title: "MENU file format" ---
MENU file format

Applies to:
BGEE, BG2EE, IWDEE (patch 2.0 and later)

General Description
MENU files (resource type 0x0408, extension .menu) define the user interface of the Enhanced Editions since patch 2.0. A MENU file is plain text. It declares menus (screens and panels), the items (controls) they contain, and the Lua code that drives them.

The engine loads exactly one MENU resource by itself: UI.MENU, read once at start-up after the engine's own Lua functions have been registered. The file is lexed and parsed in a single pass. Lua code embedded in it is compiled into the same global Lua state that the rest of the user interface uses. The Lua functions available to menu code are listed on the MENU Lua interface page, and the other globals the engine defines on the Engine Lua globals page.

This page describes the parser and the data structures it builds, as implemented in patches 2.6.6.0 and 2.7.3.0 of BGEE, BG2EE and IWDEE. All six of these builds were examined. Their keyword tables, grammars and parser tables are identical, and the few differences that exist are listed under Version differences. PSTEE and other patch levels were not examined.

Descriptions marked † are inferred from the engine's own field and function names; the code that consumes them was not traced in detail. Everything else on this page was checked against the executables.

Lexical structure
The file is read as one NUL-terminated string and split into tokens as follows:

Token Rules
White space Any character accepted by the C function isspace (space, tab, CR, LF, VT, FF) separates tokens.
Comment -- starts a comment that runs to the end of the line. A single - is a minus sign.
{ } Open and close a block.
String Text between a pair of double quotes ("…") or a pair of single quotes ('…'). The string ends at the next occurrence of its opening quote character, so the other quote character can appear inside it. There are no escape sequences, and a string can span several lines. An unterminated string runs to the end of the file.
Number A run of decimal digits, converted with atoi. There are no fractions or hexadecimal numbers: 1.5 is read as 1, a skipped . and 5. A negative value is written as - followed by a number, and the sign may be repeated (- -5 is 5).
Word A run of ASCII letters and digits that does not start with a digit. If the word matches one of the keywords, compared case-insensitively, it is that keyword; otherwise it is treated exactly like a string. Underscores are not part of a word: unquoted My_Menu is the string My followed by the keyword menu. Always quote names. A word of 64 or more characters makes the engine abort.
Inline Lua Text between two backticks (`…`) is Lua code. The lexer runs it as soon as it reaches it, under the chunk name menu, so it runs before any part of the file that follows it is parsed. It produces no token. The engine drops the last character before the closing backtick, so end every inline block with a line break or a space. A compile error or a runtime error is logged and shown in a message box, and parsing continues.
Anything else Any other character (for example , ; = ( .) is silently skipped, so area 0, 0, 10, 10 is the same as area 0 0 10 10.

Syntax errors. When a token cannot be accepted, the engine logs Invalid token in menu: [token] on line L, character C. A Menu Error message box is shown as well when the Debug Mode option of the Program Options section is set. The line number counts the line breaks before the token, so the first line of the file is line 0, and on that line the character number is meaningless. The offending token is discarded and parsing continues. Further errors are not reported until three tokens have been accepted again.

Grammar
The parser is generated by the Lemon parser generator. The grammar below was rebuilt from its tables (157 rules) and is identical in all examined builds. Quoted symbols are literal tokens. + means one or more and | separates alternatives. Keywords are case-insensitive.

file        ::= menu+
menu        ::= 'menu' '{' menu_prop+ item+ '}'
item        ::= item_type '{' item_prop+ '}'
              | 'list' '{' column+ item_prop+ '}'
item_type   ::= 'label' | 'text' | 'button' | 'edit' | 'movie' | 'slider'
              | 'handle' | 'slot' | 'map' | 'template'
column      ::= 'column' '{' column_prop+ item+ '}'
column_prop ::= 'width' value
item_prop   ::= one of the item properties below
              | item                         -- a nested item
menu_prop   ::= one of the menu properties below

number      ::= NUMBER | '-' number
value       ::= number | STRING | 'lua' STRING
color       ::= value | number number number number
halign      ::= 'left' | 'top' | 'right' | 'bottom' | 'center'
This grammar implies the following rules:
  • Every menu needs at least one menu property and at least one item, and all menu properties must come before the first item.
  • Every item needs at least one property. An empty block such as label { } is a syntax error.
  • In a list, all column blocks come first and the list's own properties follow them. Each column starts with one or more width entries and then holds one or more items.
  • The parser accepts every item property in every item type. The type only decides which fields are used when the item is drawn and handled.
  • Alignment words are interchangeable: left and top both mean 0, right and bottom both mean 1, and center means 2.

Keywords
The keyword table has 124 entries for 122 distinct words, and it is identical in all examined builds. Keywords are matched case-insensitively; the spelling below is the engine's. name and top each appear twice in the table with the same meaning, and transparent is the same keyword as usealpha.

Value forms
Form Meaning
NUMBER A literal integer. In a value it is stored as an integer constant.
STRING A literal string, used exactly as written. Where a property takes Lua code as a string (marked statement or expression in the tables), the string is compiled into a Lua function. See How a menu becomes Lua.
lua STRING A Lua expression. It is compiled into a function that returns the expression, and the function is called every time the engine needs the value.
value Any of the three forms above. A property that needs a number reads an integer constant directly, or calls the Lua function and takes its result: a number is truncated to an integer and a boolean becomes 0 or 1, while anything else, or a Lua error, gives 0. A property that needs a string reads a string constant directly, or calls the function and takes its result as a string. Integer and string constants are not converted into each other, so use the form the property expects.
color Four numbers a b c d are packed into the 32-bit value a + b×28 + c×216 + d×224. A single number or string is a key into the global Lua table fontcolors (a number is converted to its decimal text). The table entry must be a hexadecimal string, and it is read while the file is parsed. For a number key with no matching entry the colour is 0xFFFFFFFF; a string key must exist. lua "…" gives a colour that is evaluated at run time.

Menu properties
A menu is identified by its name together with its panel and state numbers. Names are compared case-insensitively. Menus are kept sorted by these three keys and found by binary search, so if two menus share all three, which one is found is unspecified. Every menu should have a name, because a missing name is passed to the string comparison as a null pointer. The engine stores at most 256 menus and does not check this limit.

Nested items. Any item can contain another item block. The parser builds items in one shared, static work record and only copies it into a new item when the closing } is reached. A nested block therefore receives every property the enclosing item declared before it, and the enclosing item starts again from defaults. Only the most recent nested block is remembered (in the enclosing item's template slot). This is why a template is written with its nested item first and its own properties after it:

template
{
	label
	{
		bam "B3TBACKG"
		scaleToClip
	}
	name "B3Timer_Menu_TEMPLATE_Background"   -- after the nested item
}
Items are kept in file order. Only top-level items are entered in nameToItem; nested items and items inside list columns are not.

Note on transparent. The engine's grammar has a rule transparent number that would set a movie's transparency, but the keyword table maps the word transparent to the same token as usealpha. That rule can never be reached: transparent n sets the BAM alpha flag, and a movie's transparency (read by Infinity_PlayMovie) cannot be set from a MENU file.

How a menu becomes Lua
Each property that takes Lua code is compiled while the file is parsed, by running a generated chunk that defines a global function. A reference to that function is then stored in the item. The global name is a fixed prefix followed by a memory address in hexadecimal (the C %p format). It is unique within one run, but it is not stable between runs, so never refer to these globals by name. Two chunk shapes are used:

function <prefix><address> () <code> end          -- statement form
function <prefix><address> () return <code> end   -- expression form
Form Properties (prefix of the generated global in parentheses)
Statementonopen (onopen), onclose (onclose), action (action), actionalt (actionalt), actiondbl (actiondbl), actionenter (actionenter), actionexit (actionexit), actionUpdate (actionupdate), actionsimpledrag (actionsimpledrag), actionsimpledrop (actionsimpledrop), actionHold (actionhold), actionScroll (actionscroll)
Expressionmenu and item enabled (enabled), actiondrag (actiondrag), table (table), bitmap res (resname), seperator (seperator), useOverlayTint (useOverlayTint), every lua STRING value (variant), and the values generated by slotinfo/spellInfo (variant_icon, variant_count, variant_usages, variant_highlight, variant_tint, variant_tooltip, variant_greyscale, variant_bam, valid, enabled, action)

The generated functions take no arguments. The code text is pasted in unchanged, so a Lua syntax error in it just leaves the function undefined; the error is not reported. Code in a property string is only compiled at load time; it runs later, so it can call functions that are defined further down in the file. In contrast, the following are evaluated during parsing and must exist before the menu that uses them: the translation function used by text STRING and placeholder, the styles table used by text style, and the fontcolors table used by color values. The usual way to provide them is an inline `…` block earlier in the file.

The parser also creates these globals:
  • One empty table per list item, named list followed by an address.
  • One global per new highlightgroup name (see Buttons above).
  • After the whole file has been parsed, nameToItem = {} is rebuilt. Then, for every top-level item with a name (menus in their sorted order, items in file order), the engine runs nameToItem['name'] = nameToItemPointer, where nameToItemPointer holds the item as light userdata. A later item with the same name replaces an earlier one. A name that contains ' breaks the generated statement and is skipped.
See the MENU Lua interface page for the globals that are set at run time and for the Lua functions that operate on menus and items.

Limits
Limit Behaviour
Menus: 256Size of the engine's menu array. The parser does not check it, so exceeding it overwrites the menu stack that follows the array in memory.
Menu stack: 256 entriesSize of the stack of open menus.
Word length: 63 charactersA longer unquoted word aborts the game. Quoted strings are not limited.
Parser stack: 100 entriesOn overflow the parser empties its stack. Ordinary nesting stays far below this limit.

Version differences
Keywords, grammar, parser tables and the property-to-field mapping are identical in all six examined builds (BGEE, BG2EE and IWDEE at 2.6.6.0 and 2.7.3.0). The only difference in the parser is this:

Example
`
-- inline Lua: runs when the lexer reaches it (note the line break before the closing backtick)
myMenuTitle = "Hello"
`

menu
{
	name "MY_MENU"            -- quoted: an unquoted name cannot contain '_'
	align center center
	ignoreEsc
	onopen "Infinity_Log('opened')"

	label
	{
		area 0 0 200 40
		text lua "myMenuTitle"    -- evaluated at run time
		text align center center
	}

	button
	{
		name "MY_MENU_CLOSE"
		area 0 50 200 40
		bam "MYBUTTON"            -- a BAM resource of your own
		enabled "true"
		action "Infinity_PopMenu()"
	}
}
